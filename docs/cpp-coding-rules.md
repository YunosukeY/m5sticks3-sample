# C++ コーディング規約

## M5GFX

### `setTextColor` は2引数版を使う

理由: 1引数版は前景色と背景色に同じ値が入り、文字セルの背景が塗られない。
同じ位置に上書きしても前の文字が残る。

## Boost.SML

### アクションとガードは、遷移表の外に名前付きラムダとして定義する

理由: SML は自由関数も関数ポインタも受け付けず、`operator()` を持つクラス型を要求する。

可読性: 遷移表が1行1遷移になり、状態遷移の構造を一覧できる。
インラインで書くと、遷移の構造がアクションの本体に埋もれる。

テスタビリティ: 名前が付いた分だけ単体で呼べる。
外部への副作用を持たないアクションは、
状態機械を動かさずにデータ構造体を渡すだけで確認できる。

### サブマシンの終了は `X` で宣言し、親は無名遷移で受ける

責務分離: 終了条件はサブマシン自身の関心事であり、親が知る必要はない。

可読性: そのサブマシンを読むだけで、いつ終わるかが分かる。

### `on_entry` は使わない。入場時の処理とデータの初期化はサブマシン先頭の `*"init"_s` 無名遷移に書く

理由: `on_entry` は内部遷移でも走るため、入場時だけの処理を書けない。
また最上位の初期状態の `on_entry` は `sm` の構築時に走るため、
`sm` をグローバルに置くと他の初期化より先に実行される。

データの初期化をここに置くのは、SML の状態が値を持てず、
データが `sm` の外に置かれて自動では戻らないため。
